WebRTC Architecture & Security

Zero-server peer-to-peer file transfer engine

How standard QR Transfer works

  1. Sender initializes: PeerJS assigns a secure, unique Peer ID to Sender A.
  2. QR Generation: Embeds URL parameter ?peer=ID into a 300x300 high-density QR code.
  3. Handshake Signaling: Receiver B scans QR code and contacts PeerJS signaling cloud to exchange SDP offers & ICE candidates.
  4. Direct P2P DataChannel: A direct encrypted WebRTC UDP/TCP stream opens between device browsers. The signaling server is bypassed completely!
  5. Stream Chunking: Files are sliced into 32KB ArrayBuffer chunks with automated flow control (backpressure handling) and assembled in receiver RAM.
End-to-End Encrypted

All WebRTC DataChannels mandate DTLS/SCTP encryption at protocol level.

Zero File Storage

Files never touch disk storage or third-party servers. 100% Client-Side memory.

Limitations

Extremely massive files (>2GB) depend on receiver device RAM capabilities. Both devices must remain online with the tab active during transfer.
